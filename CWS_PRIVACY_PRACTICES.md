# Chrome Web Store Privacy Practices — Terenval Wallet

Use this file as the canonical copy/paste guide for the Chrome Web Store **Privacy practices** tab. Re-check every answer against the exact ZIP generated by `configs/cws/release.mjs` before submission.

## Single purpose

**A non-custodial browser wallet that lets users create or import accounts, view assets, connect to compatible dApps, approve or reject signing requests, and send transactions on Ethereum, selected Ethereum Layer 2 networks, custom EVM networks, and Bitcoin.**

## Data categories

Select the following categories because the Extension processes them, even where processing is local-only.

### Personally identifiable information

**No.** The Extension does not request or use a name, email address, phone number, government identifier, or advertising identifier for wallet operation.

### Health information

**No.**

### Financial and payment information

**Yes.** Public wallet addresses, balances, assets, transaction details, transaction hashes, and signed transactions are processed for wallet functionality. Public blockchain data and signed transactions may be transmitted to RPC, blockchain-data, explorer, market-data, and broadcast providers when required by the user’s action. Seed phrases and private keys are not transmitted.

### Authentication information

**Yes — local processing.** Wallet passwords and encrypted key material are used locally to unlock and sign. Passwords, seed phrases, and private keys are not transmitted to Terenval or third-party services.

### Personal communications

**No.**

### Location

**No intentional location collection.** Analytics events do not contain location or an IP field and are not enriched using IP geolocation. Network servers can technically observe the source IP address as part of an HTTPS connection.

### Web history

**Yes — local processing only.** The Extension reads the active tab URL and origin/domain to identify a dApp request, route it to the correct tab, and remember approved domain permissions. URL/domain data is not sent in Terenval product analytics.

### User activity

**Yes.** The Extension locally processes wallet interactions and connected-site permissions. After explicit opt-in, product analytics may include an allowlisted event type, selected network/chain, feature category, asset symbol, approximate USD amount bucket, Extension version, consent version, and hour-rounded timestamp. Analytics contains no address, transaction hash, exact amount, URL/domain, or persistent analytics identifier.

### Website content

**Yes — limited local processing only.** Page title and favicon are used to identify the dApp in the approval interface. The Extension does not scrape page text, forms, credentials, or user communications, and title/favicon data is not sent in product analytics.

## Required certifications

Certify that data is used only to:

- provide the disclosed wallet purpose;
- improve wallet functionality after optional analytics consent;
- maintain security, reliability, and prevent abuse;
- comply with applicable law.

Certify that user data is not:

- sold;
- used or transferred for targeted advertising;
- used for creditworthiness, lending, or insurance decisions;
- transferred for unrelated purposes;
- used to build unrelated user profiles.

## Analytics consent

- Analytics is off until the user chooses **Enable usage analytics**.
- **Continue without analytics** is presented on the same screen.
- Consent version and timestamp are stored locally.
- Consent can be withdrawn under **Settings → General → Usage analytics**.
- Opt-out stops future transmission immediately.

## Privacy policy URL

Use: `https://terenval.com/privacy/`

The page must be public, accessible without login, served over HTTPS, and match `PRIVACY_POLICY.md` before submission.

## Permission justifications

### `storage`

Stores encrypted wallet state, public account metadata, settings, custom EVM networks, connected-site permissions, local activity, and analytics consent. Removing it would prevent the wallet from persisting accounts and settings between browser sessions.

### `tabs`

Reads the active tab’s ID, URL/domain, title, and favicon so the Extension can display the requesting dApp, associate approvals with the correct origin and account, and return the result to the correct tab. It is not used for browsing-history analytics, advertising, or page scraping.

### `clipboardWrite`

Copies a public wallet address or other public transaction-related value only after the user clicks a copy control.

### Broad HTTPS content-script matching

The provider bridge must be available on compatible dApp origins so websites can discover the wallet and request account access, signatures, or transactions. No account is exposed and no request is approved without explicit user interaction in the Extension UI. The scripts do not scrape page content or inject remote executable code.

## Remote code answer

Answer **No, this extension does not use remote code** after confirming the final ZIP contains no remotely hosted script, remote `import()`, remote `importScripts()`, `eval`, or downloaded executable logic. Blockchain, market-data, analytics, and RPC responses are data, not replacement Extension code.

## Pre-submission verification

1. Generate the ZIP only through `node packages/extension/configs/cws/release.mjs`.
2. Confirm the manifest contains only `storage`, `tabs`, and `clipboardWrite` and the expected broad content-script matches.
3. Confirm the ZIP contains only Ethereum/L2 and Bitcoin provider code and no swap, hardware-wallet, Solana, Polkadot, Kadena, Massa, Litecoin, or Dogecoin runtime.
4. Confirm remote backup is disabled and no `backupstore.enkrypt.com` reference exists in executable files.
5. Confirm analytics is off before consent and stops after opt-out.
6. Confirm analytics payloads contain no address, public key, transaction hash, exact amount, URL/domain, signature, raw transaction, seed phrase, private key, password, or persistent identifier.
7. Verify `analytics.terenval.com` is HTTPS-only, rejects unknown fields, does not log request bodies, and applies the published retention limits.
8. Publish the privacy and support pages and use `support@terenval.com` consistently.
9. Ensure the listing text and screenshots show only functions present in the submitted ZIP.
