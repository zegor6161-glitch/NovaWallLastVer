# Terenval Wallet — Chrome Web Store Submission Checklist

This is the final operational checklist for the exact ZIP submitted to Chrome Web Store.

## 1. Canonical files

- Privacy policy: `PRIVACY_POLICY.md`
- Privacy practices answers: `CWS_PRIVACY_PRACTICES.md`
- Permission explanations: `PERMISSIONS_JUSTIFICATION.md`
- Reviewer instructions: `CHROME_WEB_STORE_REVIEW_NOTES.md`
- External services: `THIRD_PARTY_ENDPOINTS.md`
- Analytics details: `TELEMETRY_DISCLOSURE.md`
- Single purpose: `CHROME_STORE_SINGLE_PURPOSE.md`
- Short listing copy: `STORE_SHORT_DESCRIPTION.txt`
- Full listing copy: `STORE_FULL_DESCRIPTION.md`
- Support details: `SUPPORT.md`

Do not copy submission text from files marked `DRAFT` unless it has first been reconciled with these canonical files.

## 2. Public pages required before submission

- Homepage: `https://terenval.com/`
- Privacy policy: `https://terenval.com/privacy/`
- Support page: `https://terenval.com/support/`
- Support email: `support@terenval.com`

Verify each page is public, HTTPS-only, accessible without login, mobile-readable, and contains the same product name and support address.

## 3. Store listing fields

**Name:** Terenval Wallet: Ethereum, L2 and Bitcoin

**Summary:** use the complete contents of `STORE_SHORT_DESCRIPTION.txt`.

**Description:** use the user-facing text from `STORE_FULL_DESCRIPTION.md` without the Markdown title if the dashboard supplies a separate name field.

**Category:** Finance.

**Language:** English for the initial listing unless localized copies have been reviewed separately.

Do not claim support for swaps, hardware wallets, remote backup, Solana, Polkadot, Kadena, Massa, Litecoin, or Dogecoin.

## 4. Graphic assets

Confirm the dashboard has:

- the final 128 × 128 store icon;
- at least one clear screenshot showing actual Extension UI;
- screenshots only from the submitted build;
- no seed phrase, private key, real wallet balance, personal address, test password, or unrelated brand;
- no visual reference to disabled networks or features;
- consistent Terenval branding and readable text.

Recommended screenshot sequence:

1. Main account and network view.
2. Supported network selector.
3. Ethereum dApp connection approval showing the requesting domain.
4. Transaction review screen.
5. Bitcoin account or send screen.
6. Analytics consent or privacy setting.

## 5. Build and artifact

Run from the repository root:

`node packages/extension/configs/cws/release.mjs`

Submit only:

`packages/extension/release/terenval-wallet-cws.zip`

Confirm:

- Manifest V3;
- production build with `CWS_RELEASE=true` and `VITE_CWS_REVIEW_BUILD=true`;
- permissions are exactly `storage`, `tabs`, and `clipboardWrite`;
- expected HTTPS content-script matches only;
- no source maps or build diagnostics;
- no remote executable code;
- no legacy Enkrypt/MEW service endpoints;
- no disabled provider, swap, hardware-wallet, or backup runtime;
- all manifest icons exist;
- build and artifact scan workflows pass on the exact commit.

## 6. Privacy practices tab

Use `CWS_PRIVACY_PRACTICES.md` as the answer key. Declare financial/payment information, authentication information, web history, user activity, and limited website content processing. Do not hide local-only processing.

Confirm the Limited Use certifications and use `https://terenval.com/privacy/` as the privacy policy URL.

## 7. Permission justifications

Paste the corresponding explanations from `PERMISSIONS_JUSTIFICATION.md` for:

- storage;
- tabs;
- clipboardWrite;
- broad HTTPS site access/provider injection.

Do not mention `unlimitedStorage`, Trezor, hardware wallets, swaps, or disabled chains.

## 8. Remote code declaration

Select **No remote code** only after the artifact scan passes. Explain that executable logic and WebAssembly are packaged in the ZIP; RPC, market, blockchain, and analytics responses are data only.

## 9. Reviewer instructions

Paste a concise version of `CHROME_WEB_STORE_REVIEW_NOTES.md`. State that no external account is required and instruct the reviewer to create or import a disposable test wallet. Never provide a seed phrase containing real funds.

## 10. Production services

Before submission verify:

- `analytics.terenval.com/product-events` is operational over HTTPS;
- unknown analytics fields are rejected or discarded;
- request bodies are not written to access logs;
- analytics and access-log retention match the privacy policy;
- analytics is off by default and opt-out stops future events;
- public privacy/support pages are live;
- all built-in RPC and market-data services respond from the packaged build.

## 11. Manual functional smoke test

Using a fresh Chrome profile:

1. Install the exact unpacked `dist` generated by the release command.
2. Create a disposable wallet.
3. Test analytics decline, then enable/disable it from Settings.
4. Test all built-in network selectors.
5. Test an Ethereum balance read and a transaction review without broadcasting real funds.
6. Test a compatible Ethereum dApp connection, rejection, signature review, and transaction review.
7. Test Bitcoin balance/UTXO loading and transaction review using disposable test data.
8. Test address copy.
9. Add and remove a custom EVM network.
10. Verify disabled features and brands are absent.
11. Inspect DevTools network traffic and compare every host with `THIRD_PARTY_ENDPOINTS.md`.

## 12. Final sign-off

Record in the PR description:

- commit SHA;
- Extension version;
- ZIP checksum;
- workflow results;
- date the public privacy policy was verified;
- date analytics infrastructure and retention were verified;
- reviewer who completed the smoke test.

Do not submit while any of these items remains unverified.
